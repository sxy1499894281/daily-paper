# Daily Paper · 每日论文书架

记录现行的中文论文日报如何选稿、核验、写作、计算热度和归档。任意 Agent 可以按同一规则生成日报 JSON，不需要依赖某个模型、聊天产品或网页。

**现行任务**：每天北京时间（Asia/Shanghai）约 09:00 更新同一个私有书架，按北京时间日期归档，保留历期。正常更新只写书架，不另发日报。这个仓库是规则和数据契约，不会启动新定时任务，也不会自动发布。

| 文件 | 用途 |
| --- | --- |
| [docs/editorial-policy.md](docs/editorial-policy.md) | 现行策略：八主题、并行选稿、证据和写作要求 |
| [docs/agent-contract.md](docs/agent-contract.md) | 建议接入方式：输入、输出、幂等发布与旧书架适配 |
| [schema/issue.schema.json](schema/issue.schema.json) | 建议的日报 JSON Schema v1.0 |
| [examples/issue.json](examples/issue.json) | 合成日报样例，包含新作、老作、数据缺失与热度计算 |

## 接入的最小路径

1. 读取选稿策略，准备北京时间日期、已归档论文索引和可用的研究来源。
2. 用支持搜索和读原文的 Agent 生成一份符合 Schema 的 JSON。主编和发布者可以是同一个进程，但检索阶段不需要写权限。
3. 验证结构、论文身份、原文证据、跨期去重和日期，再由发布适配器写入配置好的私有目的地。只编辑当天一期，写后读回校验。

建议先离线实现「生成 → 验证 → 本地 JSON 归档」，再接私有书架。仓库不包含现有书架的凭证、账号配置、历史日报或私有数据。
