# 编辑策略 v1.1（配置驱动 · 高召回新作追踪）

> 主题列表、优先级、锚点论文、关注基准与个人反馈均由 [profile/topics.json](../profile/topics.json)、[profile/watchlist.json](../profile/watchlist.json) 和 [profile/feedback.jsonl](../profile/feedback.jsonl) 驱动。编辑或增删主题时优先修改 `profile/`，本文件定义通用编辑原则。

## 核心编辑理念：宽进严标、导读优先

1. **高召回追踪近期新作，不做过度“宁缺毋滥”式漏杀**：
   - 论文的真正突破性往往需要时间沉淀才能被社区识别。对于最近 7–14 天内发表的贴题新作，**不要因为“目前没热度”或“看起来像增量”而轻易丢弃**。
   - 只要贴合主题、包含真实技术工作（非明显跑题或纯营销空壳），就应收录，并通过**1–2 句一针见血的白话导读**和**透明工程标签（`tags`）**让读者几秒钟自行决定要不要点开细读。
2. **用「两级阅读深度」平衡信息量与高召回**：
   - **`deep`（深度精读）**：Tier 1 核心主线高贴题论文、有真实在线交互评测/在线 RL/可验证环境/开源代码或环境的新作、以及高热老作与顶会获奖作。完整写清方法机制、实验基准/条件、与常见做法或锚点工作的差异，以及关键局限。
   - **`scan`（新作速览）**：其他贴题的近期新作。依然遵守一手原文核验和全部必填结构，但表述更精炼，重点突出**解决什么痛点 + 核心新意 + 客观标签（如 `offline-only`、`no-code-yet`）**，方便读者快速扫读。

## 每天查的八个主题与优先级分层

八栏每日都查，不轮换。按你的核心研究主线分为两层（具体检索词与锚点见 [profile/topics.json](../profile/topics.json)）：

| 顺序 | 主题 | 分级 | 检索重点 |
| --- | --- | --- | --- |
| 1 | Computer Use | Tier 1 核心主线 | 可执行的桌面、网页、移动或跨应用任务；工具使用、OS/Shell/GUI 混合操作、长程规划、失误恢复和实际任务成功率。 |
| 2 | 多模态编程 | Tier 2 雷达追踪 | Code→Video、Code→Image、Image→Code、Video→Code、3D Code，每项都查，允许真实可执行代码参与的其他跨模态方向。 |
| 3 | GUI Agent | Tier 1 核心主线 | UI 感知、grounding、状态验证、动作决策；重点关注真实交互、在线 RL、reward/verifier、rollout 和有条件说明的评测。 |
| 4 | 环境规模化 | Tier 1 核心主线 | 可扩展的环境合成、模拟器或 mock apps、任务与验证器生成、可复位状态与在线训练高吞吐基础设施。 |
| 5 | 递归自我改进 | Tier 2 雷达追踪 | 迭代改善策略、技能、工具、代码或 Agent 系统；检验持出集迁移与多轮退化，区分更新上下文、技能、代码和模型权重；不是金融 RSI。 |
| 6 | 游戏智能体 | Tier 2 雷达追踪 | 游戏中的学习、推理、玩测、可验证任务、游戏环境与基准，不限于游戏生成。 |
| 7 | World Model | Tier 1 核心主线 | 优先 GUI / digital world model：界面、网页、文件、应用或 OS 的状态建模、轨迹转环境、模拟和规划；区分截图、隐状态、文本/DOM 树和真实执行。 |
| 8 | Personal Agent | Tier 2 雷达追踪 | 长期记忆、偏好、私有工作空间、跨应用执行、持续适应、主动协助与权限边界。区分个人助理和特定企业岗位学习。 |

特殊栏目规则：
- **多模态编程**：Code→Video 包括像 Coda-DaVinci 那样用可执行场景程序约束视频，区分直接渲染和引导生成；普通无代码的文生图、文生视频和纯神经 3D 生成属于硬排除。栏目 `note` 注明当天五个子方向的覆盖情况，每篇必须填写 `directions`。
- **锚点说明**：锚点论文（如 `AndroidWorld`、`AppWorld`、`MobileGym`、`SoftwareGym`、`ScaleWoB`、`TRACE2WORLD`、`WildAWM`、`World Intelligence Agent`、`MyPCBench`、`ApprenticeBench` 等）用于检索扩展和实验横向定位，不作为示例重复推荐。

## 选稿四轨道与证据要求

- **近期新作（`fresh`）**：优先最近 7 天，必要时放宽到 14 天（含边界日）。重大修订可按经核验的新版本日期计算，在 `revision_note` 中说明版本及变化。采用高召回原则：Tier 1 栏目建议 3–6 篇（繁忙日最多 12 篇），Tier 2 栏目建议 2–5 篇（最多 10 篇）；确实没有新稿时如实写 `note`，不编造不硬凑。
- **高热老作（`popular_backlist`）**：与新作并行查，不等新作不够才补。每期跨主题优先选 1–3 篇超过 14 天、尚未收录且仍值得读的工作，附可点击的 `backlist_evidence`（引用、官方仓库关注、实质讨论或独立复现）；没有合格候选时说明原因。
- **获奖与专题补读（`award` / `supplement`）**：独立于老作名额。获奖以会议或论文集官方记录为准，写清会名、年份、奖项全名，区分主会、Workshop 与荣誉提名；Oral、Spotlight、Highlights、入围或录用不等于获奖。专题补读说明现在为什么值得看。
- **排重与跨栏**：用 DOI、arXiv ID（去版本后缀）、规范化标题匹配会前版/正式版和 `issues/` 历期档案；跨栏只在一个最匹配的主栏详解一次，其余关联主题记入 `secondary_topics` 或在栏目 `note` 中交叉引用。
- **一手核验**：查 arXiv、OpenReview、学会论文集和作者技术报告，确认标题、作者/机构、发表日期、版本及正文。可用社区讨论发现线索，但方法与实验结果必须回查原文；资料查不到就明确写明，绝不凭摘要猜表格。
- **首推（`lead`）**：从当期已收录论文中选 1 篇最值得优先精读的工作，给出英文原题/ID、原文直链和优先读理由；有可核实章节或表图时写进 `section_ref`。实验环境名不是论文名（例如 `MobileGym` 应出现在导读或方法中，标题用论文英文原题）。

## 每篇写什么

1. **元数据**：稳定 `id`（如 `arxiv:2610.12611`）、英文原题、发表日期、直达一手原文的 HTTPS 链接、可选 `authors_or_org` 与官方 `repo_url`。
2. **阅读深度与工程标签**：
   - `reading_tier`：`deep`（深度精读）或 `scan`（新作速览）。
   - `tags`：从 [profile/watchlist.json](../profile/watchlist.json) 选取可核验的客观标签（如 `open-code`、`open-env`、`open-data`、`online-rl`、`verifiable-reward`、`real-eval`、`offline-only`、`no-code-yet`），弥补近期新作热度冷启动问题。
3. **导读（`intro`）**：用 1–2 句白话直白讲清「解决什么问题 + 具体做了什么 + 为什么值得看（或注意边界）」，让读者看导读即可秒判兴趣。
4. **摘要译述（`abstract_zh`）**：按作者摘要顺序做完整、忠实的简体中文译述，保留背景、方法、评测及结论，不缩成一句，也不混入正文的新数字。
5. **方法论（`method`）**：写清输入、核心步骤、训练/推理或验证机制，点出与常见做法或锚点工作的区别。
6. **实验结果（`results`）**：注明任务集、指标、基线、主要数字、预算/版本等必要条件，能指到表图更好；区分百分点与相对提升，区分离线动作预测、模拟器、真实在线成功率、作者自报和独立复现。数字无法核实就明确写明。
7. **关键局限（`limitation`）**：指出至少一个影响读者如何采用或外推结论的真实限制。
8. **热度明细（`heat`）**：原始计数、来源、观察日期，可点击；与研究质量和工程价值分开呈现。

## 热度 v1：无上限，按已核实数据计算

| 维度 | 查什么 | 计分 |
| --- | --- | --- |
| 学术引用 | 按 DOI / arXiv ID 查 OpenAlex、Semantic Scholar；正式发表的查会议版或已合并记录，核对标题与作者。只选一个最可信、版本匹配的记录，不把两个索引或不同版本相加。 | 引用次数 × 3 |
| 社区讨论 | 按 arXiv ID 查 Hugging Face Papers 投票；可用有直接来源的真实讨论评论数。机器人、转载、模型点赞不等于该论文讨论。 | max(投票数 × 1，评论数 × 2)，有多来源不相加 |
| 仓库关注 | 由作者或项目页确认官方 GitHub 仓库。共享仓库注明；不能把组织、模型页或某个无关项目的热度算进来。 | 星数 × 0.1，同维度不叠加 |

三项贡献相加后四舍五入，不平均、不封顶；只有已核实的数据入分。缺项不算 0，另标覆盖度 `0–3/3`；没有任何来源显示「—」，真实的 0 则正常显示。引用旧快照注明来源和快照日，不能冒充实时数据或只取最大值。获奖可显示但不入分；复现可作选稿证据不单独入分。近期新作通常处于热度冷启动期，请结合 `tags` 与导读判断价值，不要把热度当质量排名。
