# 现行编辑策略

## 每天查的八个主题

| 顺序 | 主题 | 检索重点 |
| --- | --- | --- |
| 1 | Computer Use | 可执行的桌面、网页、移动或跨应用任务；工具使用、长程规划、失误恢复和实际任务成功率。 |
| 2 | 多模态编程 | Code→Video、Code→Image、Image→Code、Video→Code、3D Code，每项都查，允许真实代码参与的其他跨模态方向。 |
| 3 | GUI Agent | UI 感知、grounding、状态验证、动作决策；优先真实交互、在线 RL、reward、rollout 和有条件说明的评测。 |
| 4 | 环境规模化 | 可扩展的环境合成、模拟器或 mock apps、任务与验证器生成、可复位状态与在线训练吞吐。 |
| 5 | 递归自我改进（RSI） | 迭代改善策略、技能、工具或 Agent 系统；检验持出集迁移与多轮退化，区分更新上下文、技能、代码和模型权重；不是金融 RSI。 |
| 6 | 游戏智能体 | 游戏中的学习、推理、玩测、可验证任务、游戏环境与基准，不限于游戏生成。 |
| 7 | World Model | 优先 GUI / digital world model：界面、文件、应用或 OS 的状态建模、模拟和规划；区分截图、隐状态、文本树和真实执行。 |
| 8 | Personal Agent | 长期记忆、偏好、私有工作空间、跨应用执行、持续适应、主动协助与权限边界。区分个人助理和特定企业岗位学习。 |

多模态编程里，Code→Video 包括像 Coda-DaVinci 那样用可执行场景程序约束视频，区分直接渲染和引导生成；普通文生图、文生视频和无代码的纯 3D 生成不算。栏目注明当天五个子方向的覆盖情况。GUI / digital world model 可用小米 World Intelligence Agent 作检索锚点；Personal Agent 可用 MyPCBench、ApprenticeBench 作锚点，不按示例重复推荐。

## 选稿与证据

- **近期新作**：优先最近 7 天，必要时放宽到 14 天（含边界日）。重大修订可按经核验的新版本日期计算，说明版本及变化。
- **高热老作**：与新作并行查，不等新作不够才补。每期跨主题优先选 1–3 篇超过 14 天、尚未收录且仍值得读的工作。有明确引用、官方仓库关注、实质讨论或独立复现等证据；没有合格候选时说明原因。
- **获奖与专题补读**：独立于老作名额。获奖以会议或论文集官方记录为准，写清会名、年份、奖项全名，区分主会、Workshop 与荣誉提名；Oral、Spotlight、Highlights、入围或录用不等于获奖。补读说明现在为什么值得看。
- 八栏每日都查，不轮换。每栏通常 2–4 篇，合格稿集中时可增加，最多 8 篇；只有 0–1 篇达标就直说，不凑数。按贴题度、一手证据和可借鉴性优先，同等条件再看新鲜度与热度。个人排序可提高 GUI/RL、可执行跨模态代码、数字环境状态建模的权重，但不能跳过其他主题。
- 查 arXiv、OpenReview、学会论文集和作者技术报告，确认标题、作者、发表日期、版本及正文。可用讨论发现线索，但方法与结果回查原文。用 DOI、arXiv ID、规范化标题匹配会前版/正式版和历期档案；跨栏只详解一次，其余栏目交叉引用。资料查不到要说明，不能凭摘要猜表格。
- 首推写该期已收录的论文英文原题、原文直链和优先读理由；有可核实的章节或表图时给到位置。实验环境名不是论文名，例如 MobileGym 应出现在导读或方法中。

## 每篇写什么

1. 英文原题、日期、直达一手原文的 HTTPS 链接。
2. **导读**：先用 1–2 句白话讲问题和文章在做什么。
3. **摘要译述**：按作者摘要顺序做完整、忠实的简体中文译述，保留背景、方法、评测及结论，不缩成一句，也不混入正文的新数字。在引述限制下用自己的中文表达。
4. **方法论**：写清输入、步骤、训练/推理或验证机制，点出与常见做法的区别。
5. **实验结果**：注明任务集、指标、基线、主要数字、预算/版本等必要条件，能指到表图更好；区分百分点与相对提升。区分离线动作预测、模拟器、现实在线成功率、作者自报和独立复现。数字无法核实就明确写明。
6. **关键局限**：指出一个影响读者如何采用结论的限制。
7. **热度明细**：原始计数、来源、观察日期，可点击；与研究质量分开。

## 热度 v1：无上限，按已核实数据计算

| 维度 | 查什么 | 计分 |
| --- | --- | --- |
| 学术引用 | 按 DOI / arXiv ID 查 OpenAlex、Semantic Scholar；正式发表的查会议版或已合并记录，核对标题与作者。只选一个最可信、版本匹配的记录，不把两个索引或不同版本相加。 | 引用次数 × 3 |
| 社区讨论 | 按 arXiv ID 查 Hugging Face Papers 投票；可用有直接来源的真实讨论评论数。机器人、转载、模型点赞不等于该论文讨论。 | max(投票数 × 1，评论数 × 2)，有多来源不相加 |
| 仓库关注 | 由作者或项目页确认官方 GitHub 仓库。共享仓库注明；不能把组织、模型页或某个无关项目的热度算进来。 | 星数 × 0.1，同维度不叠加 |

三项贡献相加后四舍五入，不平均、不封顶；只有已核实的数据入分。缺项不算 0，另标覆盖度 0–3/3；没有任何来源显示「—」，真实的 0 则正常显示。引用旧快照注明来源和快照日，不能冒充实时数据或只取最大值。获奖可显示，但不入分。复现可作选稿证据，不单独入分。跨覆盖度或跨论文年龄不要把指数误读成质量排名；用细分去判断是长期影响还是短期讨论。
